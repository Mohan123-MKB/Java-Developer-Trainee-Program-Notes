**Dependency lookup operation:**



* If controller wants bean of service class, then controller ask bean and get bean form IOC.(it is called lookup operation) - we need ask for the dependency.
* It is not directly injected on the dependent class.(like dependency injection).
* In the container there is a spring bean of application context. if you get reference of this bean, then you can look up any other bean from the container. \[application context is default object in spring IOC container.]
* DI application context bean to your controller and then call getBean() to get the desired service bean, then we can use this service bean.

&#x20;                                 private final ApplicationContext appContext;



&#x09;			  public MyController(ApplicationContext appContext) {

&#x20;   					this.appContext = appContext;

&#x09;			  }



&#x09;			  public void execute() {

&#x20;   					Service serviceObj = appContext.getBean(Service.class);

&#x20;   					serviceObj.get();

&#x09;			  }

* currently we made java classes are spring bean with help of @Component.
* All object created by spring are available in IOC container  then only **we can inject and use this object** in any class.
* For injection are : DI, Dependency look up.

&#x20;              -DI = automatically inject object from IOC container(field injection, constructor injection\[pass dependency class object reference as parameter then we assign this reference value in variable and we use this dependency object - At the time of creation of constructor the object is injected])

&#x20;              -Dependency lookup = Need to ask for dependency with help of application Context object , it is default object present in IOC container, so with help of this object we call method of this object then we get whatever bean we want then it provide object from this  IOC container.



* @Configuration , @Bean => we will ne able to predefined classes objects as spring bean.
* Create a class with @Configuration annotation. This will tell spring that here we are defining bean configurations.
* Within  this class write method, but have return type oof the object that you will create and return. so spring manages it.
* For making predefined java class as spring bean, we need to manually create the object in this method annotated with @Bean.
* when spring reads the @Configuration class, it will look for methods with @Bean and call those methods => your code will create the object => spring will maintain it in container => now you can DI.

**Core features of Spring Boot:**



1. Spring Boot is one of the project of spring eco-system.
2. Spring Boot is totally magic happens.
3. Rapid and production level application development.
4. Focus on business logic.
5. Less Configuration, More Dependencies.
6. Convention over configuration mechanism.
7. Default Tomcat Embedded server provided by spring Boot.
8. Spring Boot **Starter =>** (automatically add some dependencies in one place as bundles so that developers might need this dependencies to build project, so it is very helpful we called as "Opinionated Starter".) - Simplifies dependency setup.
9. Spring Boot **Auto-Configuration =>** (Auto-Configuration = Spring Boot detects what you need and configures it automatically, so you focus on business logic instead of setup.)
10. Spring Boot **Actuator =>** (provides production-ready features to monitor and manage applications.)
11. **Spring Boot Profiles =>** (managing configurations in different environments.)
12. No additional setup needed and production-ready features are provided.(metrics and health monitor our application.)

**Important Concepts to Remember:**



\- IoC: Spring takes control of creating and managing configured objects.

\- Spring Bean: An object managed by the Spring container.

\- DI: Spring provides a class with its required dependencies.

\- Dependency Lookup: A class explicitly requests a bean, for example, through ApplicationContext.getBean().

\- @Component: Marks a class for component scanning.

\- @Configuration: Declares bean configuration.

\- @Bean: Registers the object returned by a method as a Spring bean.

\- Spring Boot Starter: Simplifies dependency setup.

\- Auto-Configuration: Configures components based on dependencies and application conditions.

\- Actuator: Supports monitoring and management.

\- Profiles: Support environment-specific configuration.

🔹 \*\*1. Dependency Injection vs. Dependency Lookup\*\*



\- \*\*Dependency Injection (DI):\*\* Spring provides the required dependencies to a class.

\- \*\*Dependency Lookup:\*\* A class explicitly requests a bean using `ApplicationContext.getBean()`.

🔹 \*\*2. Spring Beans: `@Configuration` \& `@Bean`\*\*



\- `@Configuration` defines a class containing bean configuration.

\- `@Bean` registers the object returned by a method as a Spring-managed bean.

\- `@Component` marks a class for component scanning.



These concepts help Spring create and manage objects that can be reused across the application.

\- \*\*Spring Boot Starters:\*\* Simplify dependency setup.

\- \*\*Spring Boot Actuator:\*\* Provides application health checks and monitoring features.
