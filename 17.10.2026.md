**API - Application Programming Interface:** 



* It is the way of two systems to communicate to each other. 
* If you wants to access data, send data, communicate, connect, interact, integrate two system then definitely need API.
* I act as an interface, bridge, communicator, connector, integrator, data exchanger between two system then definitely need API.
* Frontend and Backend integration.
* In Distributed System Environment the different software parts of applications are running on different environments or machine or system so here the communication is happening over the network in distributed system so we need API.
* REST API - It is an architectural style to defining network application and it uses http concepts. Client-Server architecture. It is the standard way to build APIs over the network.
* REST - It is a set of guidelines, principles, rules designed for developing distributed application and making API calls across the network.
* For developing web APIs we use REST guidelines are called REST API.
* Two parts of software communicate over web, http-https protocol we called as webservices.

**REST Principles:**

&#x20; **1.Client-Server** => The invoker is client it can be any software, FE, BE, any tech, any tool. Server is backend where our code is executing. Well-defined contract on how these guys can communicate with each other.



&#x20; **2.Stateless** => Each request contain all the info needed to process it, the server does not store client-state between requests. ( e.g. When multiple server instances are running then if state maintenance happen then we need to somehow sync state across all instance this include more work, complexity and might have scaling challenges. if not maintain state then failure will happen during distribute time)

so that doing stateless it means system will be lightweight and handle more load efficiently.



&#x20; **3.Cacheable** => Responses should indicate whether they can be cached to improve performance and reduce server load.



&#x20; **4.Uniform Interface** => Rest revolves around the concept of resource.

&#x20;                        To develop any Rest APIs, we need to first identify a resource.

&#x20;                        These resources can have CRUD operations.

&#x20;                        These resources can perform actions.



&#x20; **5.Layered System** =>  Clients do not need to know whether they are communicating directly with the server or through intermediaries such as gateways, proxies, or load balancers.

**Overall:**



* when client send the incoming request then it is URL endpoint so this URL endpoint is combination of http method and path and when coming this request now spring framework map one of the method in controller,  this request map to exactly one method that is unique (http method and path) then it do further action.             



* Here what we learned when incoming request comes from client that is mapped exactly one method in the controller.(The mapping is based on http method and path called URL endpoints).   



* Client uses some common http concepts to send the request to server and server uses this same http concepts to receive the request and do further action and give it responses back.
* **Http concepts:** (URL, protocol, request param, path variable, request header, request body, JSON req, xml, response body, Http Method (GET, POST, PUT..), Response status code 2xx, 3xx, 4xx, 5xx, 1xx, response header)



* Purpose is how data passes through the system, how data is flow through the system, and client is send the request to server for getting, storing ,updating, deleting some data to others system.



* We need to have a method which will be called by external people and they are send some URL endpoints to access data from one system to another system.



* We need to write a method in controller which will be invoked by the client. The client can be in any tech, the server can be in any tech. The only  things which is common between them is network and web concepts. so both are used to same concepts to communicate to each other.



* If we go to client(postman, FE, Microservice, Mobile app, browser) and make a Rest API call then our method should be executed **||** For every incoming request we need to map it to our method **||** Use "path + Http method" combination to map to your controller method **||** when a request comes like GET /test/m1 => spring framework will look for the method of one of the controller which maps to this combination and then makes that API call.
