🔹 How a Request Is Processed in My Payment Validation Service



* The client sends a payment request.
* Security validation checks the HMAC signature.
* If the request is valid, it reaches the controller.
* Field validation and business validation are performed.
* If all validations are successful, the request proceeds to payment processing.
* If any validation fails, an appropriate exception is thrown and an error response is returned.



🔹 What is Exception Handling?



* Exception handling is a mechanism used to handle errors that occur during program execution. 
* It helps prevent unexpected failures and allows the application to return meaningful error responses.



🔹 Why do we need Exception Handling?



* To handle runtime errors effectively.
* To provide clear/meaningful and human-readable error messages.
* To return appropriate HTTP status codes, such as 400, 401, and 500.
* To help users understand what went wrong and how to correct their requests.
* To maintain a smooth and predictable API response flow.

* The Spring framework handles incoming HTTP requests and invokes the appropriate controller method.
* The controller calls the service layer, and the service may call other services or repositories.
* If an exception occurs in Service2 and is not caught there, it propagates up the call stack.
* Spring MVC looks for an appropriate exception handler, such as a method defined in a class annotated with @RestControllerAdvice.
* If a matching handler is found, Spring invokes it.
* The handler prepares an appropriate error response, including the HTTP status code and error details.
* Spring sends that response back to the API client, such as Postman.
* If no custom handler matches, Spring may use its default exception handling, depending on the exception and configuration.
