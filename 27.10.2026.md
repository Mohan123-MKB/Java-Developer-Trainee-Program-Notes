**getReader() has already been called for this request \[because framework can be read only one for that request cycle]: That why this method we use:**



The servlet request body is a stream that can normally be consumed only once.

Use an HttpServletRequestWrapper to cache the body if multiple components(filters and controllers) need to read it.

We need to create a wrapper request. Read the current HttpServletRequest and put it inside WrappedRequest.

So we will read data from incomeing HttpServletRequest only once and for further operations we will pass this WrapperRequest.

So spring framework will receive WrapperRequest object and it will be able to read the request body again and call controller.

**How to handle different types of input data in HMAC Filter?**

The HmacSHA256 check we added in filters and it expects JSON input for signature generation. It works for the current request.

However since we are calling this logic in filter, so this will execute for other incoming request as well.

Current code works for this endpoint -> POST/v1/payment with JSON request body.

However if we get other variations like there is no request body and tampering can happen at path like (GET/v1/payments/123). So how to handle such situation which works across multiple circumstances.



**Solution**: Prepare the input data differently. we can use it in this format -> HTTPMethod+PATH+CannonicalJSONString. If request body is not as JSONSTRING then skip it inputData. Use this only HTTPMethod+PATH.

\------------------------------------------------------------------------------------------------------------------------------------------

**Interviewer asking why your HMAC filter is handle only JSON data?**

Our APIs will expect JSON string itself. So we can expect canonical JSON string.

Currently our APIs are protected with HMAC Filter and yes we need it for /v1/payments.

However in future if we get other endpoints to be exposed via our microservice, they might not need HMAC Filter so they might need some different filters to run.

Yes, its possible to configure all those things in SecurityFilterChain depending on our need, finalize the right configuration and use it.
