**Building blocks of IOC(why IOC): Object creation and managing concepts -> spring take for object creation and managing**



class is a template, it is a logical entity, object are created for this class then only something happen so object is a real-world entity.



Different objects of the same class behave differently based on data it holding.



As a developer always need to think when to create, when to reuse, when to release and manage properly. Otherwise memory will be full then it leads to application will slow down, hangs, crash and cannot process request further.(very dangerous concern)



That's why spring framework realized, object creation and managing should be done in optimized manner. so spring have IOC concepts it means the control to create and manage object is inverted to spring. Here spring will take care for object creation and managing everything rather than developer create and manage object manually.



As a developer whenever need object for our class then we can easily get object from spring container/IOC container then use this object, so we will only focus on business logic rather than creating and managing objects.

**What is Dependency Injection:\["How can one spring bean access another spring bean"]**



Injecting the object, object injection - whichever class need object then here spring automatically inject object from IOC container to your class.

Controller is dependent object and Service is dependency object.

Spring automatically inject required object from IOC container.



**How to implement dependency:**



1.Field Injection - @Autowired

2.Constructor Injection - use constructor to initialize spring bean (@RequiredArgsConstructor)

3.Setter injection

**Overall Note:**



* when using spring framework always try to use spring bean and avoid manually object creation.
* To make java class as spring bean and use it wherever needed. For making java class as spring bean then we use @Component annotation.
* spring will keep this object inside IOC container and provide you wherever you want it.
* If one spring bean wants to access another spring bean then we use dependency injection.
* We can implement dependency injection in 3 ways:(automatically inject object from spring/IOC container)

&#x20; 	1.Field Injection - @Autowired

&#x20; 	2.Constructor Injection - use constructor to initialize spring bean (@RequiredArgsConstructor)

&#x20; 	3.Setter injection

**Note:**



**What if you not mention @Autowired during Field injection?**



Keep @Component enabled and comment @Autowired and keep @Autowired enabled and comment @Component and check the behaviour of the framework. -> will start but throw runtime exception because we except object of another class but if not mention @Autowired then how can be dependency injection possible?? the controller come up to call method of service class then without proper service object reference inside controller class then how controller call service class method(without object of service we cant access method of service class from controller so we need to inject the dependency of service class bean then only it possible to perform an action)



**Why always prefer constructor injection rather than Field injection?**



* It is recommended since it is faster and during bean creation itself, spring injects the dependency, so works in optimized manner.
* No need to use @Autowired on field and making field final is good.
* Define controller constructor with dependency as a parameter then spring will automatically pass this dependency by picking the service bean from the container.(initialize value help of constructor -> read value form parameter then assign value to this filed).
