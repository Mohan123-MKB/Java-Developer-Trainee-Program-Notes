**Normal working flow of which have implemented HmacSHA256 in my project:(Signature based authentication)**



1. In my project currently i have building payment validation service, In this project i have implemented HmacSHA256 security algorithm, The first step validation service have one secret key/generate one secret key.

2. The secret is shared to merchant.

3. Now merchant holding this secret key and incoming JSON data, merchant now use HmacSHA256 algorithm and apply this algorithm on secret key along with JSON data then HMAC generate unique hmac-signature.

4. When merchant make any request/API call to validation service then merchant must send secret key along with the request.

5. Now the request is reached to validation service then validation service receive JSON data and same mechanism will happen again it means it will generate another hmac-signature.

6. Now validation service compares both incoming and generated signature.(Signature based Verification happen here)

7. If both are matched then the request is securely authenticated(verify the user identity/message authenticity/message validation successfully) and data integrity is maintained(no data tampered happen)

8. If both are not matched then we can confidently say the request is failed (authentication is failed) and data integrity is not maintained(data tampered happen). The below two cases will happen possibility:
 **\[Data tampering happen during requesting time,(same secret key <=> no secret key change)]** => case 1 - when merchant send the request during that time if someone(attacker) try to modify the original data before it reaches validation service then it will impact the different result(hmac signature) because validation service receive tampered data not original data so signature will be different. we can confidently say the request is invalid(authentication is failed - someone tried to modify our data) =>we not allow to do further payment process(request is rejected).

 **\[Data tampering happen during starting time,(different secret key <=> secret key change)]** => case 2 - when attacker send the request along with original data and hmac signature(this hmac signature is different because attacker don't know the secret key and he is used invalid key for generating hmac signature) to the validation service then validation service receive the JSON data and it will calculate another hmac signature then it will impact different result(hmac signature) because validation service used original secret key so signature will be different. we can confidently say the request is invalid(authentication is failed - someone tried to modify our data with invalid key) =>we not allow to do further payment process(request is rejected).
