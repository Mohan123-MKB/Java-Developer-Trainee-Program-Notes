**Main point of today session.**



When request comes then request is reached to filters, after that all filter execute one by one, it will call one another like chain and each filter have specific security rules like(authentication, authorization, role-based access). Further we have already build HmacSHA256 security now we can customize and configure this HMAC(add new filter) inside securityFilterChain. Create HmacFilter and add into securityFilterChain.When request is reached to our HmacSHA256 filter then our request is processed based on logic , once request is verified as invalid then it rejected, if it valid then we need to store this authenticated object inside securotyContextHolder, if we not store this object inside then while executing authorization filter, first it goes to securityContextHolder then it checks any authentication object is present or not. If it not present then request is denied eventhough if our request is verified as valid in HMACFilter. So that we must store the authentication object in securityContextHolder whenever our request is verified as valid. Once stored then while calling authorization filter, it will checks authentication object is present or not inside securityContextHolder. If it validate then our request reached to controller.
